# Keys this configuration deliberately takes over from stock LazyVim.
#
# Format: mode<TAB>lhs. The collision check reports anything not listed here,
# so a key taken by accident stands out from one taken on purpose.
#
# Every entry needs a reason. A key with no reason is a key nobody decided on.

# One grep key, with the filter switched inside it rather than one key each.
n	<Space>/
n	<Space>sg
n	<Space>sw
x	<Space>sw

# Buffers, where the old configuration had them. Find Files keeps <leader>ff.
n	<Space><Space>

# which-key's buffer keymaps and this config's feature list answer the same
# question, so they share one picker rather than competing for the key.
n	<Space>?

# Diffview's toggles, which close on the key that opened them. <leader>gd was
# LazyVim's hunk diff, which <leader>gh and gitsigns still cover; the diff
# viewer that handles merges is the one worth the shorter key.
n	<Space>gd
n	<Space>gf

# persistence.nvim, with wording that says what it restores.
n	<Space>qS
n	<Space>ql

# The same mapping, described in our own words.
n	<lt>Esc>

# Neovim's built-in LSP keys, which describe themselves with the function they
# call and fire in buffers with no server attached. See lua/config/lsp-keys.lua.
n	gO
n	gra
x	gra
n	gri
n	grn
n	grr
n	grt
n	grx

# The git pickers, rebound through the trust gate. LazyVim's versions run git
# directly, and a repository's own .git/config names programs git executes.
# Same pickers, refused in a project nobody has vouched for. See DECISIONS 44.
n	<Space>gs
n	<Space>gl
n	<Space>gL
n	<Space>gb

# Vim's own argument-list keys, replaced by mini.bracketed's jumps of the same
# meaning: [a and ]a move between arguments either way, and [A and ]A go to
# the first and last. Whether they show up here depends on which plugins the
# baseline happened to install, so they are written down rather than left to
# chance.
n	[a
n	]a
n	[A
n	]A
